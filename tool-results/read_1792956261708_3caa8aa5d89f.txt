    16→## Parano1d Protocol Reference (extracted from source)
    17→
    18→### JSON-RPC 2.0
    19→- Endpoint: `POST <rpc-url>` (default node: `http://127.0.0.1:9601`)
    20→- Auth: `Authorization: Bearer <mining-key>` header (for pool/external; not needed for solo localhost)
    21→- All methods namespaced `paranoid_*`
    22→
    23→### Mining methods
    24→- `paranoid_getBlockTemplate(miner_address: string) -> BlockTemplateResponse`
    25→  - `template_id: string` — single-use, expires in `expires_in_seconds`
    26→  - `pow_fields_hex: string` — 256 hex chars = 16 × 16-byte LE u128 fields
    27→  - `nonce_field_index: number` — canonical value: 10
    28→  - `difficulty_target_hex: string` — 64 hex chars = 32-byte LE target
    29→  - `height: number` (u64)
    30→  - `expires_in_seconds: number` (u64)
    31→  - `n_txs: number`
    32→- `paranoid_submitBlock(template_id: string, nonce_hex: string) -> string`
    33→  - `nonce_hex` = 16 bytes LE = 32 lowercase hex chars
    34→
    35→### PoW algorithm
    36→- Poseidon2b permutation with domain tag `TAG_POWHDR`
    37→- Input: 16 × `Block128` (= `u128`) fields, 256 bytes total
    38→- Nonce lives at field index 10 (canonical)
    39→- Hash output: 32 bytes
    40→- Valid if `hash < target` (256-bit little-endian comparison)
    41→- Block target: 30s mean, ASERT difficulty
    42→
    43→### Wallet methods (subset)
    44→- `paranoid_walletStatus -> WalletStatus` (address, balance, utxo_count)
    45→- `paranoid_walletGetAddress(index: u32) -> string` (bech32m)
    46→- `paranoid_walletGetBalance -> WalletBalance`
    47→- `paranoid_walletListUtxos -> Vec<WalletUtxoInfo>`
    48→- `paranoid_walletHistory -> Vec<WalletHistoryEntry>`
    49→- `paranoid_walletSend(to_address, amount_micronoid, fee_micronoid) -> WalletSendResult`
    50→- `paranoid_walletPlanSend(to, amount, fee) -> WalletSendPlan`
    51→- `paranoid_walletNextAddress -> WalletAddressInfo`
    52→- `paranoid_walletListAddresses -> Vec<WalletAddressInfo>`
    53→- `paranoid_walletActiveAddress -> WalletAddressInfo`
    54→- `paranoid_walletSetActiveAddress(index) -> WalletAddressInfo`
    55→- `paranoid_validateAddress(address) -> AddressInfo`
    56→- `paranoid_blockCount -> u64`
    57→- `paranoid_getChainInfo -> ChainInfo`
    58→- `paranoid_getMiningInfo -> MiningInfo`
    59→- `paranoid_getNodeStatus -> NodeStatus`
    60→- `paranoid_estimateFee(n_outputs) -> u64` (μNOID)
    61→- `paranoid_getSlotHints(count) -> Vec<u32>`
    62→
    63→### Constants
    64→- Address: bech32m, HRP `o1`, e.g. `o1...`
    65→- 1 NOID = 1,000,000 μNOID
    66→- 256-bit master spend secret (no keypair, no signature — ZK proof of knowledge)
    67→- Block time: 30s mean
    68→- Initial reward: 16 NOID, halving schedule
    69→- Miner share: 90% during dev allocation, 100% after
    70→- Poseidon2b: GF(2^128) traces, GF(2^256) Fiat-Shamir challenges
    71→- 16 PoW header fields, nonce at index 10
    72→
    73→### Stratum V2 (peakpool)
    74→- Noise-encrypted TCP (browsers can't do raw TCP — need bridge)
    75→- Solo pool, non-custodial (coinbase pays your wallet directly)
    76→- peakpool docker: `peakminer/peakpool:0.1.4` + `peakminer/parano1d-node:2.0.2`

   145→- Key decisions:
   146→  - Rust crate uses the upstream git dep (branch=main) so we always track the canonical Poseidon2b implementation. The hash logic in `hash_pow` and `batch_hash` mirrors `noid_extminer/src/main.rs` line-for-line so digests match.
   147→  - `derive_address_hex` is gated behind a `derive` cargo feature (off by default) because the upstream `SpendSecret`/`Address` newtype API isn't pinned — the wallet code paths use the node RPC `paranoid_walletGetAddress` instead.
   148→  - Android OpenCL kernel is a deliberate STUB that writes a sentinel; the C++ wrapper detects the sentinel and falls back to the CPU path through `libnoidmobile_pow.so`. A production GPU Poseidon2b over GF(2^128) is documented as future work. The app NEVER crashes if OpenCL is unavailable.
   149→  - The miner engine implements the EXACT upstream protocol: random start nonce, CHUNK_SIZE=10_000_000 split across N coroutine threads, DIGEST_BATCH=256 sub-batches, deadline = `expires_in_seconds - 1s`, `paranoid_submitBlock(template_id, nonce_le_hex)`.
   150→  - The Stratum V2 bridge is OPTIONAL — solo mode talks directly to the local node. The bridge protocol over the WebSocket is JSON, newline-delimited, with `template`/`submit`/`submit_result`/`status`/`log` shapes. The bridge holds NO wallet secrets.
   151→  - The wallet screen shows the 256-bit spend secret as a hex recovery code (NOT a BIP39 mnemonic) — BIP39 wordlist display is documented as a future enhancement. The secret is loaded into the local node and the app is a remote control via JSON-RPC.
   152→  - CI uses `GITHUB_TOKEN` (auto-provided) for WASM artifact commits + auto-fix commits + Releases. Only Android signing requires user-set secrets.
   153→  - All workflows use `concurrency.cancel-in-progress: true` so PR pushes cancel stale runs. Caching via `actions/setup-node`, `Swatinem/rust-cache`, `gradle/actions/setup-gradle`.

   338→
   339→Bug 1: ForegroundServiceTypeNotAllowed (Android 14)
   340→  - MinerService.onStartCommand called startForeground(id, notif) — 2-arg version
   341→  - On targetSdk=34 + manifest declares foregroundServiceType="dataSync",
   342→    system requires 3-arg version with the type parameter
   343→  - System threw ForegroundServiceTypeNotAllowed → app crash on START MINING
   344→  - Fix: Build.VERSION.SDK_INT check, use 3-arg startForeground with
   345→    ServiceInfo.FOREGROUND_SERVICE_TYPE_DATA_SYNC on API 34+
   346→
   347→Bug 2: JNI nullable return not handled
   348→  - NativePow.hashPowNative / batchHashNative declared as non-null ByteArray
   349→  - JNI can return null on error (env->NewByteArray fails, or rc != 0)
   350→  - Accessing .size / .toHex() on null → NullPointerException
   351→  - Fix: declare return types as ByteArray? (nullable), all callers check null
   352→
   353→Bug 3: OpenCL init could segfault
   354→  - opencl_miner.cpp declares minimal OpenCL API subset that may not
   355→    match every vendor's libOpenCL.so signature
   356→  - If CMake found libOpenCL.so, init_opencl_once() would call
   357→    clCreateContext etc with potentially wrong signatures → segfault
   358→  - Also init_opencl_once() not thread-safe (global state without mutex)

   360→    CMake option). CPU path through libnoidmobile_pow.so is always
   361→    correct and never crashes.
   362→

   364→  - Any exception propagated up and crashed the foreground service
   365→  - Fix: wrap every layer in try-catch:
   366→    * MinerService: CoroutineExceptionHandler + try-catch around runLoop

   368→    * MinerEngine.searchNonceParallel: per-worker try-catch
